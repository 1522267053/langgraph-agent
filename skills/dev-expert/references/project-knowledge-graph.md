# 依赖影响面分析（纯方法论）

> 标识仍为 `project-knowledge-graph`（历史沿用，多处引用）。**本 reference 不依赖任何外部脚本**——影响面分析全部用平台工具 `file_search`（正则搜引用）+ `file_read`（实读复核）完成。
>
> 定位：跨模块改动前的**认知加速器**，不是验证替代品。推导出的影响面清单**必须**逐个实读复核（见硬门禁 G2'）。

## 输入要求

1. **工作区根目录 `{PROJECT_ROOT}`**（必填）：项目代码根，所有 `file_search` 的 path 参数以此为准。
2. **改动文件清单**（P1 规划前置）：跨模块改动时的"本次拟改文件集"，用于查**改动闭包**而非全量。
3. **查询入口**（P2/P3）：文件相对路径，或符号名（类名/函数名，需先搜出定义位置）。

## 定位与边界

- **受众**：agent 开发时借全局视角理解项目，**不生成 mermaid**（人类可视化源，agent 不加载，纯冗余）。
- **与"任务依赖图"区分**：本 reference 是**代码结构依赖**（谁引用谁）；`task-decomposition-and-execution` / `software-project` / `refactoring` 里的"依赖图"是**任务执行依赖**（先做哪个）。命名严格拉开，不要混用。
- **与延迟加载协议互补**：查影响面替代全仓扫描，只把相关文件读进上下文。
- **与 `project-memory-management` 互补**：这里管**结构层**（代码引用关系），那里管**决策层**（为什么这么设计），互引不重叠。
- **纯加速器，非验证替代品**：正常改动靠它快定位；动刀前实读复核那一下不能省。

## 第一步：触发规模门控

| 场景 | 行为 |
|------|------|
| 简单任务 / 单文件（L0） | **不触发**，影响面分析是噪声 |
| 跨模块改动 / 重构 / 审计 / 接手陌生项目（≥3 文件） | 主动推导（先 P1 全量闭包） |
| 显式 `@project-knowledge-graph` 或"画依赖图/模块关系" | 按用户入口推导并输出清单 |
| 改完一批文件后继续改下一批 | 重新推导（上次结论可能已因本轮改动失效） |

## 第二步：推导依赖闭包

**核心动作：用 `file_search` 搜"谁引用了待改文件"，逐层向上展开。**

### 2.1 按语言选正则

| 语言 | 搜"谁依赖 X"的正则（X = 模块/文件名/类名） |
|------|------------------------------------------|
| Python | `from\s+.*X\s+import\|import\s+.*X\|X\.` |
| JS/TS | `from\s+['"].*X['"]\|require\(['"].*X['"]\|import\(.*X` |
| Vue | `from\s+['"]@?.*X['"]\|components:.*X` |
| PHP | `require.*X\|include.*X\|use\s+.*X\|new\s+\\?.*X` |
| Java | `import\s+.*X;\|extends\s+X\|new\s+X(` |
| 通用兜底 | 直接搜文件名/类名/函数名字面量 |

`file_search` 参数：`pattern=<正则>`、`path={PROJECT_ROOT}` 或子目录、`include=*.py` 等按语言过滤。

### 2.2 展开深度与预算

- **默认 2 跳**（谁引用它 → 谁又引用那些）——防止一次把半个项目读进上下文。
- **P1 规划前置**用 `both` 双向 3 跳（既看谁依赖它，也看它依赖谁）。
- **节点预算硬上限 80 个文件**：超过即截断，提示"入口太枢纽，请缩小范围或降低深度"。
- **环处理**：遍历时维护已访问集合，遇已访问节点标记 `cycle` 不再展开，杜绝 A→B→A 死循环。

### 2.3 符号名查询

符号（类名/函数名）无法直接当路径搜：先 `file_search` 搜定义（`class X` / `def X` / `function X`），拿到 `文件:行号`，再以该文件为入口按 2.1 展开。同名符号歧义 → 列出候选（每个含 `文件:行号` + 所属模块），由用户选定其一，**不要猜**。

### 2.4 产出格式

```
影响面清单（入口：<待改文件/模块>，深度：N 跳）
| 层级 | 文件:行号 | 引用形态 | 是否需同步改 |
|------|----------|---------|-------------|
| 1    | a.py:23  | from X import Y | 是（签名变更） |
| 2    | b.py:88  | a.do()          | 待实读确认 |
```

**推导结果一律标注"待实读复核"**——正则搜出的是文本命中，不等于真实依赖（见硬门禁 G2'）。

## 第三步：作用点锚定

| 作用点 | 触发条件 | 钉到 Step | 查什么 | 产出落哪 |
|--------|---------|----------|--------|---------|
| **P1 规划前置** | 复杂任务（≥3 文件 / 跨模块）进方案阶段 | **Step 2 规划（PLAN-GATE 前）** | **改动文件集闭包**（双向 3 跳），非项目全量 | 喂方案文档的依赖矩阵 |
| **P2 执行前局部** | Step 3 要改具体模块 | **Step 3 执行（改码前）** | 该模块 1~2 跳上游 | 喂查后动作规范（受影响文件一并改+验证） |
| **P3 显式请求** | 用户 `@project-knowledge-graph` 或"画依赖图/模块关系" | 任意 Step | 按用户入口 | 输出影响面清单 |
| **不触发** | 简单任务 / 单文件（L0） | — | — | 影响面分析是噪声，跳过 |

- **P1 vs P2 不冲突**：P1 全量广度（喂方案），P2 局部深度（喂执行），互补。
- **默认链路**：`复杂任务 → Step 2 前 P1 推导闭包 → 写方案依赖矩阵 → Step 3 改某模块前 P2 查上游 → 查后动作规范 → 执行`。

## 第四步：查后动作规范

拿到影响面清单后必须显式转化为执行动作，而非"看了眼"：

1. 若入口为"待改模块"，列出清单内**所有上游依赖方（谁依赖它）** → 纳入改动影响评估范围。
2. 对受影响文件清单，**在修改阶段一并改、在验证阶段一并跑 lint/断言**（防漏改依赖方）。
3. 输出"影响面摘要"给用户（改 A 会影响 B/C，已纳入范围），作为交付"已知限制/范围"的一部分。
4. **每个受影响文件都要 `file_read` 实读确认**：正则命中可能是注释、字符串、同名不同物。实读后才判定"需同步改 / 无需改"。

## 第五步：硬门禁（双保险底线）

正则推导必然漏抽动态依赖（见常见陷阱），故以下门禁是最后底线——**任一条不满足，不得交付，且 SELF-AUDIT 直接判不通过**：

- **G1 实测冲突以实测为准**：推导出的影响面与 `file_search`/`file_read` 实测不符 → 一律以实测为准，推导结果仅作提示，不得用推导覆盖实测。
- **G2' 影响面须附实读证据**：影响面清单**必须**经独立复核（对清单内每个文件确认真实依赖）；交付物须**附 `file_search` 原始输出片段**（如 `pattern="from X import" 命中 N 处 @ file:line`），SELF-AUDIT 核对证据存在且覆盖清单全部文件；**无证据即判不通过，卡在交付前**（与"无验证证据=未完成"红线同源）。agent 不能靠自评绕过谎报。
- **G3 不可逆操作单独确认**：删 / 重命名 / DDL 等不可逆操作，**不单凭推导结论**执行；必须独立 `file_search` 复核真实依赖 + 走用户确认闸门（复用既有"破坏性操作默认取消"铁律）。重命名优先用 LSP 的 `prepare_rename → rename_preview → rename_apply` 三步预览（若当前实例可用），并在汇报中贴出受影响文件清单与改动行数。

## 常见陷阱

- **动态拼路径搜不出**：`require($base.'/class/'.$c.'.php')`、`importlib.import_module(name)`、`import(resolve(dirname))`、反射/依赖注入容器注册——正则抽不出，属通用边界。**不宣称 100% 结构还原**；漏抽兜底在第四步实读复核 + 用户反馈纠偏。
- **推导 ≠ 真相**：漏抽不会报错也不会自我补全，故门禁 G1/G2'/G3 是最后底线。
- **同名不同物**：搜类名/函数名会命中多个模块的同名符号，必须看 `文件:行号` 上下文区分，不要按名字直接归并。
- **配置/字符串里的伪引用**：正则命中可能落在注释、文档字符串、配置键名里，实读才能判定是否真实依赖。
- **改完即失效**：本轮改动可能让上次推导的清单过期；连续改多批文件时，每批开始前重新推导受影响部分。
- **枢纽模块爆炸**：入口是 `settings`/`utils`/`base` 这类被全项目引用的模块时，2 跳就会超 80 文件上限——此时应改为"按调用点搜具体符号"而非"按文件搜引用"。
