# 智能体平台 — 项目定位与使用说明

> 基于 LangGraph 的轻量级 AI 智能体可视化编排平台

---

## 一、项目定位

**一句话定位**: 个人/小团队友好的"开箱即用型"AI 智能体构建与编排平台，对标 Dify 但主打 **低部署门槛 + 高编排能力**。

核心差异化优势：

1. **部署极轻** — 默认 SQLite 单进程零配置启动（Dify 需 9+ 容器），个人电脑一行命令即可运行
2. **编排能力最全** — 同类中唯一同时具备「可视化拖拽 + 循环节点 + 嵌套子流程」的开源平台
3. **插件即放即用** — 目录扫描 + 装饰器自动注册，新增节点/Provider/路由零配置扩展

### 与同类项目对比

| 维度 | 本项目 | Dify | OpenClaw | DeerFlow |
|------|--------|------|----------|----------|
| **部署门槛** | 个人零配置（SQLite），团队轻量（MySQL + Docker，2-3 容器） | 9+ 容器，部署门槛高 | VPS + Node.js | Docker 多容器 |
| **可视化编排** | 拖拽画布 + 条件分支 + 循环 + 嵌套子流程 + 意图路由 | 有画布，无循环/嵌套子流程 | 无可视化，YAML/CLI | 无可视化，Skill 文件驱动 |
| **循环控制** | 计数/条件/forEach 三种，顺序 + 并发，嵌套校验 | 不支持 | 不支持 | 不支持 |
| **流程复用** | 能力卡片，子图递归嵌套，变量隔离 | 工作流模板，无运行时嵌套 | 无 | 子 Agent 编排（非可视化） |
| **记忆系统** | 三层（热/温/冷）自动升降温 + AI 总结 + 访问衰减 | 短期对话记忆，无分层 | 会话级短期记忆 | Mem0 长期记忆（分层未实现） |
| **知识库** | 三层导航 + AI 知识沉淀 + 向量/LIKE 回退 | RAG 知识库，检索成熟 | 无内置 | 无内置 |
| **人工交互** | LangGraph 原生 interrupt()，多轮交互，前端弹窗恢复 | 人工审核节点 | Wait for Input | 无 |
| **MCP 集成** | 持久化会话 + 自愈重连 + 工具缓存 + DB 状态持久化 | 支持 | 工具函数调用 | 支持 |
| **扩展方式** | 放文件即生效（目录扫描 + 装饰器） | 内置节点为主，扩展需改代码 | Skill 文件 | Skill + SubAgent |

## 二、目标客户

| 层级 | 用户画像 | 核心诉求 |
|------|---------|---------|
| **个人开发者** | Python/AI 爱好者、独立开发者 | 本地一行命令跑起来，零运维成本，可定制专属工具节点 |
| **小型团队/初创** | 5-30 人团队、内部工具组 | MySQL + Docker 2-3 容器即可上线，无需专职运维 |
| **非技术业务人员** | 通过 Agent 模式（对话式）使用 | 不写代码，拖拽画布构建智能体，或直接用现成 Agent |

**不适合的场景**: 需要企业级多租户、SSO 单点登录、高并发、细粒度权限管控的大型企业（这些是 Dify 等重型平台的领域）。

## 三、能用来做什么

### 1. 双模式架构

| 模式 | 说明 | 允许的节点 |
|------|------|-----------|
| **Flow** | 可视化工作流编排，Start → End 完整流程 | 全部 19 种节点 |
| **Agent** | 对话式 AI 助手，单 LLM + 工具节点 | 排除 card/loop/human，memory 和 agenda 仅 Agent 可用 |

### 2. 19 种节点类型

| 节点类型 | 说明 | 可用模式 |
|---------|------|---------|
| **start** | 流程入口，定义输入参数 | Flow / Agent |
| **end** | 流程出口，定义输出变量 | Flow / Agent |
| **llm** | 大模型调用，ReAct 循环 + 流式推理 + 工具调用 | Flow / Agent |
| **condition** | 条件分支，AND/OR 逻辑 + 12 种运算符 | Flow / Agent |
| **card** | 能力卡片，引用其他流程作为子图执行 | Flow |
| **loop** | 循环节点，计数/条件/forEach 三种，顺序或并发 | Flow |
| **intent_router** | 意图路由，LLM 判断意图后分支 | Flow / Agent |
| **mcp** | MCP 工具提供者（不加入执行图，仅工具发现源） | Flow / Agent |
| **knowledge** | 知识库，三层导航 + AI 知识沉淀 | Flow / Agent |
| **memory** | 三层记忆（热/温/冷），仅 Agent 模式 | Agent |
| **human** | 人工输入，LangGraph interrupt 暂停等待响应 | Flow |
| **api** | 外部 API 调用（GET/POST/PUT/DELETE），支持文件上传下载 | Flow / Agent |
| **skill** | 技能加载，LLM 读取 Markdown 技能文档并自主执行 | Flow / Agent |
| **python** | Python 代码沙箱执行，AST 级安全隔离 | Flow / Agent |
| **shell** | Shell 命令执行 | Flow / Agent |
| **todo** | 任务计划，LLM 自主任务拆分与进度跟踪 | Flow / Agent |
| **agenda** | 日程管理，LLM 自主创建/查询/更新/删除日程 | Flow / Agent |
| **sub_agent** | 子 Agent 调用，引用已发布 Agent 作为子任务执行器 | Flow / Agent |

### 3. 典型应用场景

| 场景 | 组合方式 |
|------|---------|
| **智能客服** | Start → 意图路由 → 条件分支 → LLM + 知识库 → End |
| **文档批处理** | Start → forEach 循环 → PDF 解析 → LLM 摘要 → End |
| **数据 ETL** | Start → API 拉数据 → Python 清洗 → 条件分流入库 |
| **定时巡检机器人** | APScheduler 定时触发 → Flow 执行 → 异常告警 |
| **研究助手** | Agent 模式 + Skill 系统 + 记忆 + MCP 工具 |
| **内容创作** | LLM 节点 + 媒体生成工具（图片/音频/视频） |
| **审批工作流** | Start → LLM 处理 → Human 节点暂停 → 人工确认 → 继续 |
| **多步骤 RAG** | Start → 知识库检索 → 条件判断（是否够用）→ 循环补充 → LLM 总结 |

### 4. 集成的能力底座

| 能力 | 说明 |
|------|------|
| **6 家大模型** | DeepSeek、OpenAI 兼容、Anthropic、通义千问、智谱AI、MiniMax |
| **MCP 协议** | 持久化会话 + 自愈重连 + 工具缓存 + DB 状态持久化 |
| **知识库** | ChromaDB 向量检索 + 三层文档导航（文档→标题树→段落）+ AI 知识沉淀 |
| **三层记忆** | 热（每次注入 prompt）/ 温（向量检索）/ 冷（归档），自动升降温 + AI 总结 |
| **Skill 系统** | Markdown 技能文档，LLM 自主理解并执行 |
| **流式推理** | 支持 DeepSeek thinking、Anthropic thinking 推理过程流式输出 |
| **媒体生成** | 图片/音频/视频生成（OpenAI/Anthropic/MiniMax） |
| **定时任务** | 基于 APScheduler 的 Cron 定时触发，支持 Flow/Agent 执行目标 |
| **日程管理** | 完整 CRUD + FullCalendar 日历视图 + 提醒推送 |
| **Python 沙箱** | AST 级安全隔离，50+ 黑名单模块 |
| **执行追踪** | 完整的节点级执行记录和状态追踪 |

### 5. 部署形态

| 形态 | 适用场景 | 说明 |
|------|---------|------|
| **本地开发** | 个人试用/开发 | `poetry run uvicorn main:app --reload`，SQLite 零配置 |
| **EXE 打包** | 个人/小团队交付 | Nuitka 编译源码保护 + PyInstaller 打包，双击即可运行 |
| **Docker** | 团队部署 | MySQL + 应用层，2-3 容器上线 |
| **生产部署** | 正式环境 | gunicorn 多 worker + FastAPI 托管前端静态文件 |

## 四、变量引用约定

- `input.xxx` — 访问流程输入参数
- `variables.xxx` — 访问流程变量（其他节点的输出）
- `output.xxx` — 访问输出数据
- `nodes.{node_key}.xxx` — 访问指定节点的输出变量（子流程中常用）

无前缀时按 **context > input > variables** 优先级自动查找。

## 五、快速启动

```bash
# 后端（默认 SQLite，零配置）
poetry install
cp .env.example .env
poetry run uvicorn main:app --reload    # 端口 8000，自动打开浏览器

# 前端开发模式
cd frontend
npm install && npm run dev              # 端口 3000
```

首次访问进入初始化向导 `/setup`，可设置登录密码（可选）。
